    DNS

    OCI DNS is served under /20180115 on port 4599: zones, their records, and private views. Real OCI serves it on the dns.{region}.oci.oraclecloud.com host.

    Supported operations

    Area Operations
    Zones CreateZone, GetZone, ListZones, UpdateZone, DeleteZone, ChangeZoneCompartment
    Zone records GetZoneRecords, UpdateZoneRecords, PatchZoneRecords
    Domain records GetDomainRecords, UpdateDomainRecords, PatchDomainRecords, DeleteDomainRecords
    RRSets GetRRSet, UpdateRRSet, PatchRRSet, DeleteRRSet
    Views CreateView, GetView, ListViews, UpdateView, DeleteView, ChangeViewCompartment
    Resolvers GetResolver, ListResolvers, UpdateResolver, ChangeResolverCompartment, ListResolverEndpoints (always empty)

    Not emulated: steering policies and their attachments, TSIG keys, DNSSEC (dnssecState: ENABLED), zone transfers and secondary zones (zoneType: SECONDARY), zone migration, CreateZoneFromZoneFile, and resolver endpoints (CreateResolverEndpoint answers 501). Those that have a route answer 501 MethodNotImplemented; the others have no route.

    Wire notes

    • Zones by name or OCID: every zone path takes zoneNameOrId. A name without scope means the GLOBAL zone of that name. With scope=PRIVATE, a name also needs viewId, or the request is 400 MissingParameter, as the SDK documentation says.
    • Create: answers 201 with the zone, etag and Location. The zone is ACTIVE at once.
    • scope defaults to GLOBAL, zoneType to PRIMARY, resolutionMode to STATIC and dnssecState to DISABLED.
    • A PRIVATE zone needs a viewId (400 MissingParameter) naming an existing view (400 RelatedResourceNotAuthorizedOrNotFound). A GLOBAL zone with a viewId is 400 InvalidParameter.
    • A zone name is unique among GLOBAL zones, and among the zones of one view (409 Conflict).
    • A trailing dot on the name is dropped.
    • Delete: DeleteZone, DeleteView, DeleteRRSet and DeleteDomainRecords answer 204, and remove the resource at once; a later GET is 404.
    • List shapes: ListZones and ListViews return bare arrays. ListZones also sends opc-total-items. Zone summaries leave out nameservers, externalMasters and externalDownstreams, as ZoneSummary does.
    • Records: every record read and write returns {"items": [...]} with opc-total-items, opc-next-page and the zone's etag. Records sort by domain by default (also rtype, ttl). Each record carries domain, rtype, rdata, ttl, isProtected, recordHash and rrsetVersion.
    • Protected apex records: every zone is created with an SOA record and four NS records at its apex, marked isProtected. Adding, removing or replacing them is 400 InvalidParameter. A PUT that lists them unchanged (the OCI CLI's own test sends the whole zone back) is accepted, and a PUT that leaves them out keeps them.
    • Versions: a write that changes the records raises the zone serial by one. version is the serial as a string. Every RRSet that changed, and the SOA, carry the new rrsetVersion; the SOA rdata shows the new serial; the etag changes.
    • PATCH: the operations apply in order to a copy, and the result is stored only if all of them succeed.
    • An operation selects records by any of recordHash, domain, rtype and rdata; ttl is not a selector.
    • REQUIRE with no match, or PROHIBIT with a match, fails the whole request with 412 NoEtagMatch.
    • ADD adds a record, or sets the TTL of one that is already there. ADD with a ttl and no rdata sets the TTL of the whole RRSet, as the SDK documents. The result must still pass the record set rules below.
    • REMOVE removes every match; removing nothing succeeds.
    • On a domain or RRSet path, domain and rtype default to the path's, and a different value is 400 InvalidParameter.
    • PUT replaces every unprotected record in its scope (zone, domain, or RRSet).
    • Record set rules: the records a PUT or PATCH would store are checked as a whole before anything is stored, and a violation is 400 InvalidParameter:
    • a CNAME is the only record at its domain, so there is at most one, with nothing beside it (RFC 1034 section 3.6.2). The apex holds SOA and NS, so it can never hold a CNAME;
    • all records of one RRSet (domain and rtype) share one ttl (RFC 2181 section 5.2). To change the TTL of an RRSet, PUT it whole or ADD a ttl with no rdata.
    • Domains must lie within the zone (400 InvalidParameter).
    • Conditional requests: If-Match on every write is checked against the zone or view etag (412 NoEtagMatch). If-None-Match on GetZone, GetView and the record reads answers 304 when it matches.
    • Views: CreateView answers 201 with an etag, ACTIVE. A view that still holds zones cannot be deleted (409 Conflict).
    • OCIDs use dns-zone, dnsview and dnsresolver, with the region in the OCID.

    VCN resolvers

    Every VCN has a VCN-dedicated resolver. The DNS service creates it, with a protected default view, when Networking creates the VCN, and removes both, with the zones in that view, when the VCN is deleted. GetVcnDnsResolverAssociation in Networking names it.

    • Resolver: isProtected: true, ACTIVE, in the VCN's compartment, with the VCN's display name, attachedVcnId and defaultViewId. There is no CreateResolver or DeleteResolver in the API.
    • UpdateResolver sets displayName, tags, attachedViews (each viewId must be an existing view: 400 RelatedResourceNotAuthorizedOrNotFound) and rules. A rule must be FORWARD with destinationAddresses and sourceEndpointName, as ResolverForwardRuleDetails requires. Terraform's oci_dns_resolver creates and deletes through it.
    • ChangeResolverCompartment moves the resolver and its default view; zones stay where they are.
    • Default view: protected, so it cannot be updated, moved or deleted (400 InvalidParameter). A private zone at or under oraclevcn.com cannot be created in it (400 InvalidParameter), as the SDK documentation says.
    • Attached views: a view a resolver still attaches cannot be deleted (409 Conflict). A default view deleted with its VCN is removed from every other resolver that attached it, and those resolvers get a new etag.
    • Not used for resolution yet: the embedded DNS server answers from every zone, whatever view it is in and whichever resolver attaches it.

    Resolution from containers

    The embedded DNS server answers from the zones of the DNS service, so the sidecar containers floci-oci starts resolve the records managed through the API.

    • Who gets it: the containers started with Floci's resolver: OKE's k3s node, the Functions fnserver, PostgreSQL and MySQL DB systems, and container instances. Their /etc/resolv.conf names the embedded server. A container instance's containers share its pause container's network namespace, and with it that resolver.
    • Only in a container: the server starts only when floci-oci itself runs in Docker (as with docker compose). On the host, the sidecars keep Docker's resolver; set FLOCI_OCI_DNS_HOST_PORT to query the server from the host with dig @127.0.0.1 -p <port>.
    • Which zones: every ACTIVE zone of every tenancy, region and view, GLOBAL and PRIVATE alike. The most specific zone covering a name answers it. When several zones share that name, the oldest answers and the collision is logged at debug level. Views do not scope resolution yet.
    • Answers: A, AAAA, CNAME, NS, SOA and TXT records, authoritative, with each record's TTL.
    • A CNAME is followed through the zones floci-oci holds, up to 8 links, and each link is answered under its own name. A chain that leaves those zones ends at the last CNAME.
    • A name with no records of the asked type is NODATA, and a name the zone does not hold is NXDOMAIN, both with the zone's SOA in the authority section. A CNAME chain that ends at such a name answers the CNAMEs and adds the SOA of the zone it ends in, so the negative-cache TTL holds.
    • Other types (MX, SRV, CAA and the rest) answer NODATA.
    • Names outside every zone are forwarded upstream as before.
    • Changes apply at once: the server reads the zones on every query.

    Limits

    • OKE: k3s's CoreDNS forwards to the node's /etc/resolv.conf, so pods should resolve zone records through the node (inferred from k3s's defaults; not covered by a test).
    • Functions: only fnserver is given the resolver. Function containers are created by fnserver's Docker driver, which never sets DNS servers on them (local/oracle/fn api/agent/drivers/docker/docker.go builds a HostConfig without Dns, and cookie.go sets only the network mode), so functions keep Docker's resolver and do not see zone records.
    • No wildcard records (*.example.com) in resolution, and no zone transfers.
    • UDP only: an answer larger than 512 bytes is truncated (TC), and there is no TCP fallback.

    RDATA normalization

    OCI says "All RDATA is normalized and the returned presentation of your RDATA may differ from its initial input". floci-oci applies the transforms that Terraform's normalizeRData undoes (terraform-provider-oci/internal/service/dns/dns_record_resource.go), so a plan after an apply is empty:

    Type Stored and returned as
    A the IPv4 address; anything else is 400 InvalidParameter
    AAAA the compressed IPv6 form: 2001:0db8:85a3:0000:0000:8a2e:0370:7334 becomes 2001:db8:85a3::8a2e:370:7334; an IPv4-mapped address stays IPv6, as ::ffff:192.0.2.1
    ALIAS, CNAME, DNAME, NS, PTR the name with a trailing dot
    MX the preference and the exchange with a trailing dot
    TXT, SPF every word or quoted string as its own quoted string: v=spf1 ~all becomes "v=spf1" "~all"

    Other types keep their rdata with whitespace collapsed.

    Inferred behaviour

    These points are not stated by the OCI SDKs, the CLI or the Terraform provider, and follow the closest evidence:

    • Seeded SOA and NS: the Terraform provider skips protected records when it deletes an RRSet, which implies protected records exist; their values are floci-oci's own. The nameservers are ns1 to ns4 under dns.localhost.floci.io, and the SOA is ns1.dns.localhost.floci.io. hostmaster.<zone>. <serial> 3600 600 604800 1800, with TTLs 300 (SOA) and 86400 (NS).
    • Status codes: 201 for CreateZone and CreateView, 204 for the deletes (the SDK documents 204 for DeleteZone), 200 for the compartment moves. No DNS work request API exists, so no opc-work-request-id is sent.
    • 412 code: Oracle's error catalog has one 412 code, NoEtagMatch, which is what a failed REQUIRE or PROHIBIT sends. Terraform only checks the 412 status.
    • Record set rule errors: the SDKs, CLI and Terraform provider state no OCI check or error for a CNAME beside other records, several CNAMEs at one name, or mixed TTLs in one RRSet. floci-oci applies the RFC rules (RFC 1034 section 3.6.2, RFC 2181 section 5.2) and answers 400 InvalidParameter, the catalog's code for an invalid parameter; both the check and the code are inferred.
    • Protected-record errors are 400 InvalidParameter. DeleteDomainRecords at the apex removes only the unprotected records.
    • recordHash is an MD5 of the domain, type, rdata and TTL. zoneVersion is accepted and ignored: no history is kept.
    • GLOBAL zones are regional in floci-oci: they live in the region the request addressed.
    • OCID types dns-zone, dnsview and dnsresolver, all regional.
    • VCN resolvers: the resolver and default view take the VCN's display name; the resolver is isProtected: true; the VCN's deletion removes the zones of its default view; FORWARD rules are stored without checking sourceEndpointName, since no endpoints exist; the association's etag is the VCN's; a VCN's deletion detaches its default view from the other resolvers that attached it.
    • GetRRSet for an RRSet with no records answers 200 with no items.
    • A record PUT without items (an empty body or "items": null) is 400 MissingParameter and changes nothing. items is optional in the SDK models, but Terraform always sends a list, and an empty list [] is how a caller asks to remove the records.
    • IPv4-mapped AAAA rdata is returned in the mixed notation RFC 5952 section 5 recommends (::ffff:192.0.2.1). Terraform compares AAAA through Go's net.ParseIP(...).String(), which prints both forms the same, so either echo gives an empty plan.
